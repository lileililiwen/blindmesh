Task order follows this table; dependency edges are authoritative. Runtime → Identity → Projects/Capabilities/Credits → Task publication → Participation → Evidence → Moderation → Reputation/Notifications → Pilot. Independent siblings remain separately accepted; no consumer silently implements a prerequisite. Runtime remains infrastructure plus a usable availability shell, not completed marketplace value. Credits includes wallet UX with its ledger primitives. Evidence includes completion review and settlement because submission cannot become a usable accepted outcome without its escrow disposition; arbitration is a separate owner/state lifecycle.

Architecture decisions are in docs/architecture.md. Each package owns one canonical capability of the same name and promotes it only after verified implementation. Cross-package calls use owning services and the shared transaction; later consumers do not redefine earlier contracts. The original PRD remains unchanged; C#/.NET is the user's selected implementation language.
